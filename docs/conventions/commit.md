# Commit Rules

커밋 메시지는 아래 형식을 따른다.

```text
type: 작업 내용
```

## 작성 규칙

- 작업 내용은 한글 한 문장으로 간략히 작성한다.
- 상세 내용은 커밋 메시지가 아닌 PR 설명에 작성한다.
- 파일을 논리 단위로 묶어 커밋한다. 여러 커밋은 한 번에 순차 생성한다.

## 프로세스

1. 변경된 파일을 논리 단위로 그룹핑한다.
2. 각 그룹의 커밋 타입과 한 문장 메시지를 결정한다.
3. `git add [파일] && git commit` 을 그룹 수만큼 체이닝해 한 번에 실행한다.

```bash
git add <그룹1 파일> && git commit -m "feat: 앱 셸 레이아웃 구현" && \
git add <그룹2 파일> && git commit -m "feat: Route Group으로 레이아웃 분리" && \
git add <그룹3 파일> && git commit -m "docs: 실행 계획 문서 추가"
```

## Types

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 수정 (코드 변경 없음)
- `style`: 코드 포맷팅, 세미콜론 등 스타일 변경 (논리 변경 없음)
- `refactor`: 리팩토링 (기능 변화 없음)
- `test`: 테스트 관련 코드 추가/수정
- `chore`: 빌드, 패키지 매니저 설정 등 기타 작업
- `design`: CSS 등 사용자 UI 디자인 변경
- `comment`: 필요한 주석 추가 및 변경
- `rename`: 파일 혹은 폴더명 수정 또는 이동만 수행한 경우
- `remove`: 파일 삭제만 수행한 경우
- `!HOTFIX`: 긴급한 치명적 버그 수정
