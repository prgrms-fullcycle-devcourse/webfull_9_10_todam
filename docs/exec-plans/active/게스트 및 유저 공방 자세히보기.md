- Goal: Guest·User 모두 `/stores/[slug]` 경로에서 PUBLISHED 공방의 상세 정보(기본정보·이미지·편의정보·클래스 목록·리뷰 미리보기·지도·찜 상태)를 조회한다.

## Status

## Context

- 요구사항명세서(고정): docs/requirements.md — `공방 store` 도메인 §4 공방 조회, `/stores/[slug]` 접근 규칙 (Guest·User 동일 고객 뷰, Partner 본인 공방 예약 버튼 비활성화, 비PUBLISHED → 404)
- 기능명세: `공방 자세히보기` (기능명세 DB `b242ee66b06c8349805601ce4a05247a` — 실행주체: guest·user, 도메인: store, 연관화면: 공방 상세)
- API명세: 아래 4개 엔드포인트 (API명세 DB `5852ee66b06c838bb8ec01c6bf4f2e25`)
  - `GET /stores/{slug}` — 공방 상세 조회 (퍼블릭)
  - `GET /stores/{slug}/programs` — 프로그램 목록 (퍼블릭)
  - `GET /stores/{slug}/reviews` — 공방 리뷰 목록 (최대 3개 미리보기)
  - `POST /stores/{storeId}/favorite` — 찜 등록/해제 (User만, 토글)
- Relevant design docs: DESIGN.md (작업 시작 조건 — 캐러셀 variant, 찜 버튼 상태별 토큰, 클래스 카드 size·gap·radius, 리뷰 카드 토큰)
- Open decisions:
  - (CONTRACT-1) `GET /stores/{slug}` 응답에 공방 이미지 목록(`images[]`)·좌표(`lat`/`lng`) 포함 여부 미확정. 현 API명세 응답에 이미지·좌표 필드 없음. 캐러셀·지도 표시 요구사항을 충족하려면 BE 추가 필요 — BE 확정 후 Contract 갱신.
  - (CONTRACT-2) 찜 상태 초기값 조회 방법 미확정. 현 API는 `POST /stores/{storeId}/favorite` (토글)만 있음. 공방 상세 진입 시 현재 찜 상태를 GET으로 조회하는 별도 엔드포인트 필요 여부 또는 `GET /stores/{slug}` 응답에 `isFavorite` 포함 여부 — Guest는 항상 false, User는 서버 사이드 계산 필요.
  - (CONTRACT-3) 리뷰 미리보기 3개는 FE에서 `limit=3`으로 호출할지, BE에서 별도 "미리보기" 파라미터를 지원할지 미확정.
  - (UI-1) 지도 컴포넌트: Kakao Map SDK 사용 여부·래핑 컴포넌트 존재 여부 확인 필요. 좌표 없으면 지도 대신 주소 텍스트만 표시하는 폴백 UI 필요.
  - (UI-2) 공유 기능: Web Share API 사용 여부, URL 복사 폴백 처리 범위.
  - (UI-3) Partner가 본인 공방 접근 시 예약 버튼 비활성화 조건: `GET /stores/{slug}` 응답에 `partnerId`가 포함되어 있어 현재 로그인 유저의 파트너 ID와 비교 가능. 단, partnerId가 응답에 포함됨을 확인해야 함.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string(UUID) | 공방 ID |
| `partnerId` | string(UUID) | 파트너 ID (본인 공방 예약 버튼 비활성화 판단용) |
| `slug` | string | 공방 슬러그 |

| `phone` | string | 대표 연락처 |
| `address` | string | 도로명 주소 |
| `status` | `PUBLISHED` | 공개 상태 (비PUBLISHED는 404 반환) |
| `convenienceInfo.parking` | boolean | 주차 가능 여부 |
| `convenienceInfo.pet` | boolean | 반려동물 동반 여부 |
| `convenienceInfo.wifi` | boolean | Wi-Fi 여부 |

| 필드 | 타입 | 설명 |
|------|------|------|

| `description` | string | 한 줄 설명 |
| `price` | number | 가격 (원) |

| `thumbnailUrl` | string | 대표 썸네일 URL |
| `status` | `ACTIVE` | 노출 상태 |
| `sortOrder` | number | 노출 순서 |

| 필드 | 타입 | 설명 |

#### 3. `GET /api/v1/stores/{slug}/reviews` — 공방 리뷰 목록

- 가드: 없음
- Request: Path `slug`, Query: `page`(기본 1), `limit`(기본 10), `sort`(`latest` | `rating_high`, 기본 `latest`)
- 미리보기 3개 표시: `?page=1&limit=3&sort=latest` 로 호출 (CONTRACT-3 참고)
- 노출 우선순위 (기능명세): 이미지 포함 > 본문 포함 > 최신순 — 현 API 명세는 `latest`/`rating_high`만 지원. sort 파라미터 확장 필요 가능성.
- Response `200 OK`:
  ```json

    "timestamp": "2026-05-25T21:00:00.000Z",
    "path": "/stores/todam-studio/reviews",

        {

          "rating": 5,

          "photos": [
            { "thumbnailUrl": "https://cdn.todam.app/reviews/review-uuid-001/01_thumb.jpg" }
          ],
          "programTitle": "물레 체험 기초반",

        "currentPage": 1,
  ```

- 에러:
  - `404 STORE_NOT_FOUND`
  - `500 INTERNAL_SERVER_ERROR`

#### 4. `POST /api/v1/stores/{storeId}/favorite` — 찜 등록/해제 (토글)

- 가드: `AuthGuard` (User 이상, Guest 사용 불가)
- Request Headers: `Authorization: Bearer {accessToken}`
- Path: `storeId` — 공방 UUID (slug가 아님. `GET /stores/{slug}` 응답의 `store.id` 사용)
- Body: 없음
- Response `200 OK`:
  ```json
  {
    "statusCode": 200,
    "timestamp": "2026-05-27T02:35:00.000Z",
    "path": "/stores/store-uuid-001/favorite",
    "message": "공방 찜 상태가 성공적으로 변경되었습니다.",
    "data": {
      "storeId": "store-uuid-001",
      "isFavorite": true
    },
    "error": null
  }
  ```
- 에러:
  - `401 UNAUTHORIZED` — "찜하기 기능을 이용하려면 로그인이 필요합니다."
  - `404 STORE_NOT_FOUND`
  - `500 INTERNAL_SERVER_ERROR`

## Scope

- In:
  - **BE**: `GET /api/v1/stores/{slug}` 퍼블릭 엔드포인트 구현 (가드 없음, PUBLISHED만 조회, 이미지·좌표 필드 추가 확정 후).
  - **BE**: `GET /api/v1/stores/{slug}/programs` 퍼블릭 엔드포인트 구현 (ACTIVE 클래스만, sortOrder 오름차순).
  - **BE**: `GET /api/v1/stores/{slug}/reviews` 퍼블릭 엔드포인트 구현 (페이지네이션·정렬 파라미터 지원).
  - **BE**: `POST /api/v1/stores/{storeId}/favorite` 구현 (AuthGuard, 토글 방식).
  - **UI**: `/stores/[slug]` 공방 상세 페이지 구현
    - 이미지 캐러셀 (CONTRACT-1 해소 후)
    - 공방 기본정보 섹션 (공방명·소개·평점·리뷰 수·연락처·주소)
    - 편의정보 섹션 (주차·반려동물·Wi-Fi)
    - 운영 클래스 목록 섹션 (클래스 카드 — 가격·소요시간)
    - 리뷰 미리보기 섹션 (최대 3개, "전체 보기" 링크 → `/stores/[slug]/reviews`)
    - 지도 섹션 (CONTRACT-1 해소 후, 폴백: 주소 텍스트)
    - 찜 버튼 (User만 활성, Guest 클릭 시 로그인 유도)
    - 공유 버튼
    - 예약 CTA 버튼 (본인 공방 Partner는 비활성)
  - **MSW**: `GET /stores/:slug`, `GET /stores/:slug/programs`, `GET /stores/:slug/reviews`, `POST /stores/:storeId/favorite` 핸들러 추가
  - **연동**: 계약 타입 정의, react-query 훅(`useStoreDetail`, `useStorePrograms`, `useStoreReviews`), 찜 토글 뮤테이션
- Out:
  - `/stores/[slug]/reviews` 리뷰 전체보기 페이지 (별도 기능 `공방 리뷰 전체보기`)
  - `/classes/[id]` 클래스 자세히보기 페이지 (별도 기능 `클래스 자세히보기`)
  - 예약 플로우 (`/classes/[id]/reserve`)
  - 찜한 공방 목록 (`/my/favorites`)
  - Admin 패널 (어드민 전용)
  - Partner 공방 관리 화면 (파트너센터 전용)

## Plan

### BE

1. `GET /api/v1/stores/{slug}` 구현
   - `StoreController`에 `@Get('stores/:slug')` 추가 (가드 없음)
   - `GetPublicStoreDetailUseCase`: `stores` 테이블에서 `slug`로 조회 → `status != 'PUBLISHED'`이면 `NotFoundException` → 응답 DTO 직렬화
   - 이미지 목록(`store_images`)·좌표(`lat`/`lng`) 포함 여부는 CONTRACT-1 확정 후 추가 (Open decisions 해소 선행)
2. `GET /api/v1/stores/{slug}/programs` 구현
   - `GetPublicStoreProgramsUseCase`: `slug`로 공방 조회 → PUBLISHED 검증 → `programs` 테이블 `status=ACTIVE`, `sortOrder ASC` 조회
3. `GET /api/v1/stores/{slug}/reviews` 구현
   - `GetPublicStoreReviewsUseCase`: `slug`로 공방 조회 → PUBLISHED 검증 → `reviews` 테이블 페이지네이션 + 정렬 적용 → `totalCount`·`averageRating` 함께 반환
4. `POST /api/v1/stores/{storeId}/favorite` 구현
   - `ToggleFavoriteUseCase`: `AuthGuard` 적용 → `favorite_stores` 테이블 존재 여부 확인 → 없으면 insert (`isFavorite: true`), 있으면 delete (`isFavorite: false`)

## Risks

- CONTRACT-1: `GET /stores/{slug}` 응답에 이미지·좌표 미포함. 캐러셀·지도 UI 구현 차단 가능성. BE 설계 시 `store_images` 조인 및 좌표 필드 노출 여부 확정 필요.
- CONTRACT-2: 찜 상태 초기값 조회 방법 미확정. 공방 상세 진입 시 `isFavorite` 값 없으면 FE는 항상 false로 초기화 → 실제 찜 상태 불일치 UX 문제 발생.
- CONTRACT-3: 리뷰 미리보기 정렬 우선순위(이미지 포함 > 본문 포함 > 최신순)가 현 API 파라미터로 표현 불가. `sort` 파라미터 확장 또는 BE 내부 정렬 로직 협의 필요.
- 찜 API path 불일치: 명세는 `POST /stores/{storeId}/favorite`, MSW mock은 `POST /stores/:storeId/like`. 실 구현 path 확정 필요.
- 공방 상세 `isFavorite` 필드: 인증 여부에 따라 서버에서 계산해야 할 수 있음 (optional auth 패턴 필요).
- 지도 SDK 미확정: Kakao Map 클라이언트 사이드 초기화 필요. 좌표 없을 경우 폴백 UI 합의 필요.

## Decision Log

- 기능명 "게스트 및 유저 공방 자세히보기"는 기능명세 DB에 정확 일치 없음 → 후보 중 "공방 자세히보기"로 매칭 (실행주체: guest·user, 도메인: store, 연관화면: 공방 상세로 일치 확인).
