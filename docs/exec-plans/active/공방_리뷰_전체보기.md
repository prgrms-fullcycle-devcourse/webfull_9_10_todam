# Feature Plan: 공방 리뷰 전체보기

## Summary

- Goal: 공방 상세 페이지의 "리뷰 더보기" 진입점에서 해당 공방의 전체 리뷰 목록을 조회·표시한다. Guest/User 모두 접근 가능하며 페이지네이션과 정렬 옵션을 제공한다.

- Date: 2026-06-02

- [ ] UI 구현
- [ ] API 연동

## Context

- 요구사항명세서(고정): docs/requirements.md — `# 리뷰 review` 섹션, 특히 `5. 리뷰 조회 > 공방 퍼블릭 페이지`
- 기능명세: 공방 리뷰 전체보기 (Notion 기능명세 DB b242ee66b06c8349805601ce4a05247a)
- API명세:
  - `GET /stores/{slug}/reviews` — 공방 리뷰 목록 (Notion API명세 DB 5852ee66b06c838bb8ec01c6bf4f2e25)
  - `GET /stores/{slug}/programs/{programId}/reviews` — 프로그램 리뷰 목록 (동 DB, 클래스 상세 탭에서 활용)
- Relevant design docs: DESIGN.md (UI 규칙 — 리뷰 리스트 컴포넌트 variant·상태별 토큰 확인 필요. 현재 미확인 상태. Open decisions #1 참고)
- Open decisions:
  1. **UI 토큰/variant 미확인**: DESIGN.md에서 리뷰 카드 컴포넌트의 variant enum, 사이즈별 height/padding/gap/radius, 상태별(empty·loading·error) 토큰이 명시되어 있지 않음. 작업 시작 전 DESIGN.md 확인 또는 디자이너에게 스펙 요청 필요.
  2. **이미지 확대보기 구현 방식**: 기능명세에 "리뷰 이미지 확대보기를 제공한다"고 명시되어 있으나 구체적인 UI 패턴(Modal, Lightbox, 별도 페이지 등)이 미결정.
  3. **프로그램 리뷰 필터 연동 시점**: 리뷰 전체보기 페이지에서 특정 프로그램 기준 필터링 UI 제공 여부. 기능명세는 공방 단위 조회만 명시하나 API는 프로그램 단위 엔드포인트도 존재함.

### 데이터 모델

#### ReviewSummary (공방 리뷰 목록 아이템)

```typescript
{
  id: string;                   // 리뷰 UUID
  nickname: string;             // 작성자 닉네임
  rating: number;               // 별점 1~5
  content: string | null;       // 리뷰 본문 (선택)
  photos: Array<{
    thumbnailUrl: string;       // 240x240 썸네일 URL
  }>;
  programTitle: string;         // 대상 클래스(프로그램)명
  createdAt: string;            // ISO 8601
}
```

#### Pagination

```typescript
{
  currentPage: number;
  totalPages: number;
  limit: number;
}
```

### 엔드포인트 1 — 공방 전체 리뷰 목록

**GET /stores/{slug}/reviews**

인증 불필요 (Guest 포함 전체 접근). `PUBLISHED` 공방에 한해 조회 가능.

Request:
```
Path:  slug (string) — 공방 슬러그
Query: page  (number, 기본값: 1)
       limit (number, 기본값: 10)
       sort  (enum: "latest" | "rating_high", 기본값: "latest")
Headers: Accept: application/json
```

## Scope

- In:
  - `GET /stores/{slug}/reviews` BE 엔드포인트 구현 (공방 리뷰 목록, 페이지네이션, 정렬)
  - `GET /stores/{slug}/programs/{programId}/reviews` BE 엔드포인트 구현 (프로그램 필터)
  - 공방 리뷰 전체보기 페이지 UI (`/stores/[slug]/reviews/page.tsx` — 현재 stub)
  - 리뷰 카드 컴포넌트 (별점, 닉네임, 본문, 썸네일, 날짜, 프로그램명)
  - 정렬 탭 UI (`latest` / `rating_high`)
  - 페이지네이션 또는 무한스크롤 UI
  - 빈 상태(empty) 화면
  - 이미지 썸네일 확대보기 (Open decision #2 결정 후 구현)
  - `@todam/shared` 에 `StoreReviewListResult` contract 타입 추가
  - MSW mock handler 추가 (`GET /stores/:slug/reviews`)
  - 실 API 연동 (MSW 제거 후 실 BE 엔드포인트로 교체)

- Out:
  - 리뷰 작성 / 수정 / 삭제 기능 (별도 plan)
  - 파트너 답글 기능 (MVP 이후)
  - 리뷰 신고 기능 (MVP 이후)
  - 파트너 전용 리뷰 관리 화면 (MVP 이후)
  - 공방 상세 페이지 내 대표 리뷰 3개 노출 (공방 상세 plan에서 처리)

## Plan

### BE 구현

1. **도메인 엔티티 및 리포지터리 정의**
   - `apps/api/src/modules/review/domain/entities/` — `Review`, `ReviewPhoto` 엔티티 클래스 작성
   - `apps/api/src/modules/review/domain/repositories/` — `IReviewRepository` 인터페이스 정의 (findByStoreSlug, findByProgramId with pagination+sort)
   - `apps/api/src/modules/review/domain/value-objects/` — `Rating` 값 객체 (1~5 범위 검증)

2. **인프라 계층 구현**
   - `apps/api/src/modules/review/infrastructure/persistence/` — TypeORM 기반 `ReviewRepository` 구현체
   - slug → storeId JOIN 쿼리 작성, `PUBLISHED` 상태 공방 필터, 소프트 삭제 리뷰 제외 조건
   - 정렬 분기 (`latest`: `createdAt DESC`, `rating_high`: `rating DESC, createdAt DESC`)
   - 페이지네이션: `offset = (page - 1) * limit`, `COUNT(*)` 포함

3. **애플리케이션 계층 구현**
   - `apps/api/src/modules/review/application/use-cases/` — `GetStoreReviewsUseCase`, `GetProgramReviewsUseCase`
   - `apps/api/src/modules/review/application/dto/` — `GetStoreReviewsQueryDto` (page, limit, sort 유효성 검사), 응답 DTO
   - `apps/api/src/modules/review/application/mappers/` — 엔티티 → 응답 DTO 매핑

4. **프레젠테이션 계층 구현**
   - `apps/api/src/modules/review/presentation/controllers/` — `StoreReviewController`
     - `GET /stores/:slug/reviews` 라우트 (`@Get(':slug/reviews')`, 인증 미적용 — Public)
     - `GET /stores/:slug/programs/:programId/reviews` 라우트
   - Swagger `@ApiOperation`, `@ApiResponse` 데코레이터 추가

5. **모듈 등록**

## Risks

- `slug → storeId` 조인 쿼리 성능: 리뷰 수가 많을 경우 인덱스(`store.slug`, `review.store_id`, `review.created_at`) 누락 시 N+1 또는 풀스캔 발생 가능. 인덱스 마이그레이션 파일 작성 필수.
- 썸네일 URL 만료: API 명세의 `thumbnailUrl`이 CDN 공개 URL인지 signed URL인지 미명시. 공방 상세의 이미지 처리 패턴(`S3 공개 URL`, PR #100 참조)을 따라야 하나, 리뷰 이미지는 별도 확인 필요.
- 이미지 확대보기 시 `imageUrl`(원본) 필요: 현재 API 명세에는 썸네일만 포함. 원본 이미지 URL이 별도 필드로 필요하다면 API 명세 보완 요청 필요 (Open decision #2와 연관).
