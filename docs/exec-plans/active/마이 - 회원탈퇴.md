## API Contract (스냅샷)

<!-- Notion API명세 `DELETE /users/me` 기준 고정. BE/FE/reviewer SSOT. -->

### 데이터모델

| 모델 | 필드 | 비고 |
|---|---|---|
| `User` (`users`) | `id`, `email`, `name`, `phone`, `status`(UserStatus), `withdrawnAt`, `updatedAt` | 탈퇴 시 `status = 'WITHDRAWN'`, `withdrawn_at = now()`, email/name/phone → 해시 익명화 |
| `OAuthAccount` (`oauth_accounts`) | `userId`, `provider`, `providerUserId` | 탈퇴 시 전면 삭제 |
| `RefreshToken` (`refresh_tokens`) | `userId`, `token`, `expiresAt` | 탈퇴 시 해당 유저 전체 삭제 |

`enum UserStatus`: `ACTIVE`, `WITHDRAWN`, (`DELETED`) — 5년 후 자동 전이.

### 엔드포인트

#### `DELETE /users/me` — 회원 탈퇴

**인증:** `Authorization: Bearer {accessToken}` (AuthGuard, payload `{ sub: userId }`)

**Headers:**
```
Content-Type: application/json
Accept: application/json
Authorization: Bearer {accessToken}
```

**Request Body (이메일 가입 유저):**
```json
{
  "password": "Password1234!"
}
```

**Request Body (소셜 가입 유저):**
```json
{
  "oAuthAccessToken": "social_access_token_for_unlink_verification"
}
```

**시스템 처리:**
1. AuthGuard로 accessToken 검증, `userId` 추출. 미인증 401.
2. **탈퇴 불가 조건 검증:**
   - `reservations` 에서 해당 userId의 `status IN ('PENDING', 'CONFIRMED')` 건 존재 시 400 `ACTIVE_RESERVATIONS_OR_ARTWORKS_EXIST`.
   - `artworks` 에서 해당 userId와 연동된 작품 중 최종 완료/종료(`COMPLETED`, `CANCELED`, `DELIVERED`, `PICKUP_DONE` 제외) 진행 중 작품 존재 시 400 `ACTIVE_RESERVATIONS_OR_ARTWORKS_EXIST`.
   - (요구사항 추가) `partner` 에서 `status = 'APPROVED'` 보유 시 파트너 해지 선행 필요 → 별도 에러 코드 미정(D-3).
3. **본인 재확인:**
   - 이메일 유저: `password` 해시화 후 DB 비교 → 불일치 시 400 `PASSWORD_MISMATCH`.
   - 소셜 유저: `oAuthAccessToken`으로 외부 인증기관 검증 → 실패 시 400 `PASSWORD_MISMATCH`.
4. `users` 테이블: `status = 'WITHDRAWN'`, `withdrawn_at = now()`, 개인정보(email/name/phone) → 해시 익명화.
5. `oauth_accounts` 에서 userId 연동 레코드 전면 삭제. (카카오·Google unlink API 호출 — D-2와 연계)
6. `refresh_tokens` 에서 userId 전체 삭제.
7. 응답 헤더에 `Set-Cookie: refresh_token=; Max-Age=0; HttpOnly; Secure` 로 쿠키 만료.
8. 200 반환.

**200 OK (공통 봉투 `data` 본문):**
```json
{
  "statusCode": 200,
  "timestamp": "2026-05-25T16:40:00.115Z",
  "path": "/users/me",
  "message": "회원 탈퇴가 정상적으로 처리되었습니다.",
  "data": null,
  "error": null
}
```
> FE는 200 수신 후 localStorage `accessToken` 제거 → 메인화면(`/`) 이동 [D-4 확정].

**에러:**

| status | error code | message |
|---|---|---|
| 400 | `PASSWORD_MISMATCH` | "본인 확인을 위한 인증 정보가 일치하지 않습니다." |
| 400 | `ACTIVE_RESERVATIONS_OR_ARTWORKS_EXIST` | "진행 중인 클래스 예약 또는 제작 중인 도자기 작품이 남아있어 탈퇴가 불가능합니다." |
| 401 | `UNAUTHORIZED` | "인증 정보가 유효하지 않거나 만료되었습니다." |
| 500 | `INTERNAL_SERVER_ERROR` | "회원 탈퇴 처리 중 서버 내부 오류가 발생했습니다." |

> 요구사항에 정의된 에러(`진행 중 Partner capability 존재`) 코드는 API명세 미정 → D-3.

## Risks

- **BE user 모듈 전무**: `apps/api/src/modules/user/` 전체가 `.gitkeep` stub. 모듈 초기 구성 + UserRepository 구현이 선행 필요. 다른 user plan과 병렬 작업 시 merge 충돌 가능.
- **소셜 재인증(D-2)**: 소셜 유저의 `oAuthAccessToken` 획득 방법이 FE에서 불명확. Kakao/Google SDK 재인증 플로우 없으면 소셜 탈퇴는 별도 구현 필요. MVP에서 소셜 탈퇴 범위를 패스워드 재확인 없이 처리할지 결정 필요.
- **파트너 capability 검증(D-3)**: 요구사항은 `APPROVED` Partner 보유 시 파트너 해지를 선행 요구하나, API명세에 해당 에러 코드 미정. BE에서 단순 400으로 막을지, 에러 코드 확정 필요.
- **익명화 전략**: 요구사항은 "해시 식별자로 치환"만 정의. 정확한 포맷(prefix/hash 길이) 미정. 5년 보관 후 DELETED 전이 스케줄러는 MVP Out이나 `withdrawnAt` 필드는 반드시 기록 필요.
- ~~**진입점 위치(D-1)**~~ — RESOLVED: Figma "마이 - 회원탈퇴 - 모달"(8505:19284)에서 진입점 = 개인 정보 수정 화면(`/my/profile`) 하단 푸터 "탈퇴하기" 링크로 확정. 단, `ProfileEditScreen`(개인 정보 수정) 자체가 아직 미구현(#185 미완)이라 진입 링크는 그 화면 구현과 함께 추가해야 함.
