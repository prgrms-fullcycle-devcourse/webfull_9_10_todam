### 공통 응답 봉투

모든 응답은 기존 인터셉터 패턴을 따른다.

```
{ statusCode, timestamp, path, message, data, error }
성공: error: null, data에 페이로드
실패: data: null, error에 도메인 코드 문자열
```

### 데이터모델 (출처: `apps/api/prisma/schema.prisma`)

```prisma
model PolicyVersion {
  id          String     @id @default(uuid()) @db.Uuid
  policyType  PolicyType  @map("policy_type")
  version     String      @db.VarChar(20)
  url         String      @db.VarChar(500)   // 노션 약관 링크
  isLatest    Boolean     @default(false) @map("is_latest")
  effectiveAt DateTime    @map("effective_at") @db.Timestamptz(6)
  createdAt   DateTime    @default(now())
  consents    UserConsent[]
  @@map("policy_versions")
}

enum PolicyType {
  PRIVACY_POLICY          // 개인정보 수집·이용 동의
  TERMS_OF_SERVICE        // 서비스 이용약관
  MARKETING               // 마케팅 수신 동의 (이 시트엔 미노출, 별도 처리)
  LOCATION_BASED_SERVICE  // 위치기반 서비스 이용약관 (Decision 1 확정: 신규 추가, 마이그레이션 필요)
}
```

**FE ground truth(`apps/web/src/features/auth/terms/model/termsContent.ts`):** 바텀시트는 `service`(→`TERMS_OF_SERVICE`) / `location`(→`LOCATION_BASED_SERVICE`) / `privacy`(→`PRIVACY_POLICY`) **3종**. `MARKETING`은 이 시트에 미노출. 각 항목은 FE에 `required`(하드코딩) + `notionUrl`(현재 placeholder) 보유.
**Decision 1 확정(2026-06-11):** `LOCATION_BASED_SERVICE` enum 신규 추가 + prisma 마이그레이션. (위치정보법 제18조상 위치동의는 별도 선택 동의 — 분리 enum이 법적으로도 타당.)
**⚠️ FE 핸드오프 별건:** FE는 현재 `location: required:true`로 두는데 법적으로 **선택**이어야 함 → FE 버그. 본 plan 범위 밖, FE팀에 별도 전달.

### 엔드포인트 `GET /policies/latest` — 최신 약관 링크 조회

- 인증: **불필요(PUBLIC)** — 가입 화면 진입 시(인증 전) 호출됨. `AuthGuard` 미적용.
- 쿼리파라미터: 없음.
- req body: 없음.

**zod 스키마 (shared contract 신설 대상)**

```typescript
// packages/shared/src/contracts/policy.ts (신규)

export const policyVersionItemSchema = z.object({
  policyType: z.enum(['PRIVACY_POLICY', 'TERMS_OF_SERVICE', 'MARKETING', 'LOCATION_BASED_SERVICE']),
  version: z.string(),                 // e.g. "v1.0"
  url: z.string().url(),               // 노션 링크
  effectiveAt: z.string().datetime(),  // ISO 8601
  // Decision 3 확정(2026-06-11): isRequired 미포함. 필수/선택은 FE config 유지, API는 url/version만 동적 제공.
});
export type PolicyVersionItem = z.infer<typeof policyVersionItemSchema>;

export const latestPoliciesResponseSchema = z.object({
  policies: z.array(policyVersionItemSchema),
});
export type LatestPoliciesResponse = z.infer<typeof latestPoliciesResponseSchema>;
```

- 쿼리 조건: `WHERE is_latest = true` (타입당 1개 최신 가정)
- 정렬: 결정 대기(Open decision 2) — 기본값 `policyType` 알파벳순 또는 `effectiveAt` 최신순.

시드 row가 없으면 빈 배열 반환. 404가 아닌 이유: 약관이 0건인 상태는 운영 초기에 일시적으로 발생 가능하며 클라이언트가 graceful fallback 처리해야 함.

| 500 | `INTERNAL_SERVER_ERROR` | DB 조회 실패 |

### Open decisions — **전부 확정(2026-06-11)**

1. **[확정] `LOCATION_BASED_SERVICE` enum 신규 추가.** FE 시트가 `location`을 노출하므로 enum 추가 + prisma 마이그레이션. (위치정보법상 별도 선택 동의 대상이라 분리 enum이 타당.)
2. **[확정] 정렬 = `policyType` enum 순 고정.** FE가 순서 렌더링하므로 BE가 보장: `TERMS_OF_SERVICE → PRIVACY_POLICY → LOCATION_BASED_SERVICE → MARKETING`.
3. **[확정] `isRequired` 미포함 — FE config 유지.** API는 `policyType/version/url/effectiveAt`만. 필수/선택은 법적으로 정해져 거의 안 바뀌고, 본 기능 목표는 **URL 동적화**이므로 required는 FE 유지. (마이그레이션 컬럼 추가 없음.)
4. **[확정] "최신" 판정 = `isLatest=true` 플래그.** 약관 업데이트 시 ops가 새 row 추가하며 명시적 전환(실수 방지).
5. **[확정] 경로 = `GET /policies/latest`.** 모델명 `PolicyVersion` 일치. (FE-facing 네이밍 이견 시 팀 합의로 변경 가능하나 본 plan 잠정 확정.)
6. **[대기·비차단] 시드 링크.** 실제 노션 링크 + 버전은 ops(사용자) 제공 예정. 미제공 시 placeholder URL로 시드 작성 후 실링크 교체. 위치: `apps/api/prisma/` 하위 시드(`seed-policies.ts` 또는 기존 seed에 추가).

## Risks

- **Open decision 1 미결 시 enum 불일치(高)**: FE 바텀시트 3종 중 "위치기반 서비스 이용약관"이 `PolicyType` enum에 대응값 없음. 미결 상태로 시드 작성 시 위치기반 약관 row를 삽입할 수 없어 FE 바텀시트 연동이 불완전해진다.
- **시드 데이터 미제공(中)**: 실제 노션 링크 미확정 시 FE 바텀시트 "보기" 클릭이 placeholder로 연결됨. ops 링크 제공 전까지 연동 검증 불완전.
- **이메일 회원가입 D1~D3 drift 미해소와의 의존성(中)**: 이 plan의 시드가 없으면 회원가입 `user_consents` 생성 시 `isLatest` PolicyVersion을 찾지 못해 실패. 회원가입 연동 전 본 plan의 시드 작업이 선행돼야 한다.
- **`isRequired` 없을 때 FE 렌더링 불완전(中, Open decision 3 미결)**: MARKETING을 필수로 표시하면 UX/법적 문제. FE가 `policyType`으로 하드코딩 대응해도 되나 유지보수 취약.
- **빈 배열 응답 시 FE graceful fallback(低)**: 시드 없거나 DB 장애 시 약관 시트가 빈 상태로 열릴 수 있음. FE에서 빈 배열 케이스 UX 처리 필요.
