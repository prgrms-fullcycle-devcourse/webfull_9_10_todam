### 데이터모델 (apps/api/prisma/schema.prisma — 신규/연관 추정)

찜 도메인 모델은 정본 요구사항에 별도 엔티티 정의가 없으나 API명세 시스템 처리("favorite_stores join stores")로 추정:

| 모델 | 필드 | 비고 |
|---|---|---|
| `FavoriteStore` (`favorite_stores`) | `id`(uuid, = 응답 `favoriteId`), `userId`(uuid, FK User), `storeId`(uuid, FK Store), `createdAt`(DateTime) | `@@unique([userId, storeId])` — 중복 찜 불가(기능명세 "중복 찜 불가"). 토글 시 이력 없으면 생성, 있으면 삭제. |
| `Store` (`stores`) (연관) | `id`, `name`, `category`, `status`(StoreStatus), 대표 이미지(thumbnail), `address` | join 대상. 목록 응답은 **`status = PUBLISHED`** 만 반환. `category` 는 D2-b 로 응답 포함. |

`enum StoreStatus`(기존 `@todam/shared`): `DRAFT`, `PENDING`, `PUBLISHED`, `SUSPENDED`.

### 엔드포인트

#### 1) `POST /stores/{storeId}/favorite` — 공방 찜 등록 및 해제 (토글)

찜 이력 없으면 생성(`isFavorite: true`), 있으면 제거(`isFavorite: false`). **Request body 없음** (path param `storeId` 만).

**Headers:** `Content-Type: application/json`, `Accept: application/json`, `Authorization: Bearer {accessToken}`
**Path:** `storeId: string(uuid)`
**Request body:** 없음.

**시스템 처리:**
1. 토큰으로 사용자 식별 (AuthGuard). 미인증 시 401.
2. `storeId` 공방 조회 — 비존재/비공개(`!= PUBLISHED`) 시 404(또는 409 — D4 미정).
3. `(userId, storeId)` 찜 이력 조회 → 없으면 생성(`isFavorite: true`), 있으면 삭제(`isFavorite: false`).

**200 OK (정본 그대로):**
```json
{ "storeId": "store-uuid-001", "isFavorite": true }
```
> 정본 예시는 `data` 객체 본문만 제시. 공통 봉투 `{ statusCode, timestamp, path, message, data, error }` 의 `data` 에 위 객체가 들어가는 형태로 가정(다른 엔드포인트 정합 — D6).

| 필드 | 타입 | 출처 | 비고 |
|---|---|---|---|
| `storeId` | `string(uuid)` | path param echo | |
| `isFavorite` | `boolean` | 토글 결과 | `true` = 등록됨 / `false` = 해제됨 |

**에러:**

| status | code | message | 비고 |
|---|---|---|---|
| 401 | `UNAUTHORIZED` | "찜하기 기능을 이용하려면 로그인이 필요합니다." | 정본 그대로 |
| 404 / 409 | (정본 본문 비어있음 — **스펙 미정**) | — | 삭제·비공개 공방 찜 불가. D4 |
| 500 | `INTERNAL_SERVER_ERROR` | (정본) | |

#### 2) `GET /users/me/favorite-stores?cursor&limit` — 찜한 공방 목록 조회

커서 기반 페이지네이션. `favorite_stores join stores`, **`PUBLISHED` 공방만** 반환, 최신 찜 등록순 정렬(기능명세 "최신 찜 등록순").

**Headers:** `Accept: application/json`, `Authorization: Bearer {accessToken}`
**Query:** `cursor?: string`(선택), `limit?: number`(기본 10 — 정본. 단 팀 공통 상수 `DEFAULT_PAGE_SIZE`(20) 와 drift — D7)

**200 OK (정본 그대로):**
```json
{
  "favoriteStores": [
    {
      "favoriteId": "fav-uuid-101",
      "storeId": "store-uuid-001",
      "name": "토담 공방 성수점",
      "category": "도자기",
      "imageUrl": "https://cdn.todam.app/stores/todam-studio/01_thumb.jpg",
      "address": "서울특별시 성동구 성수이로 12길",
      "createdAt": "2026-05-26T12:00:00.000Z"
    }
  ],
  "nextCursor": "fav-uuid-101"
}
```
> 정본 예시는 `category` 미포함이나, **D2-b 결정으로 추가**(카드 카테고리 태그 렌더용 + 타 도메인 정합 — `reservation-list` 가 이미 `category: z.string()` 사용). BE 응답에 `Store.category` 추가 요청 필요.

| 필드 | 타입 | 출처 | 비고 |
|---|---|---|---|
| `favoriteStores[].favoriteId` | `string(uuid)` | `FavoriteStore.id` | 목록 key / 커서 단위 |
| `favoriteStores[].storeId` | `string(uuid)` | `Store.id` | 공방 상세 이동 / 찜 토글 대상 |
| `favoriteStores[].name` | `string` | `Store.name` | 공방명 |
| `favoriteStores[].category` | `string` | `Store.category` | **D2-b 추가** — 카드 카테고리 태그(예 "도자기"). `reservation-list.category` 와 동일 컨벤션(`z.string()` 자유 문자열) |
| `favoriteStores[].imageUrl` | `string` | `Store` 대표 이미지(썸네일) | 기능명세 "대표 이미지는 썸네일" |
| `favoriteStores[].address` | `string` | `Store.address` | 위치 표시 |
| `favoriteStores[].createdAt` | `string(ISO8601)` | `FavoriteStore.createdAt` | 정렬 기준(최신 찜순) |
| `nextCursor` | `string \| null` | 마지막 항목 `favoriteId` 또는 null | 다음 페이지 없음 = null. **`hasMore` 필드 없음** — reservation-list 와 drift(D7) |

**에러:**

| status | code | message | 비고 |
|---|---|---|---|
| 400 / 401 / 404 / 409 | (정본 본문 비어있음 — **미정**) | — | 401 은 공통 `UNAUTHORIZED` 보정 가정 |
| 500 | `INTERNAL_SERVER_ERROR` | (정본) | |

### zod 스키마 제안 (`packages/shared/src/contracts/favorite.ts` 신설)

```ts
// 공방 찜 토글 (POST /stores/:storeId/favorite — body 없음).
export const toggleFavoriteResultSchema = z.object({
    storeId: z.string(),
    isFavorite: z.boolean(),
});
export type ToggleFavoriteResult = z.infer<typeof toggleFavoriteResultSchema>;

// 찜한 공방 목록 (GET /users/me/favorite-stores).
export const favoriteStoreItemSchema = z.object({
    favoriteId: z.string(),
    storeId: z.string(),
    name: z.string(),
    category: z.string(), // D2-b: 카드 카테고리 태그(예 "도자기"). reservation-list.category 와 동일 컨벤션.
    imageUrl: z.string(),
    address: z.string(),
    createdAt: z.string(), // ISO 8601
});
export type FavoriteStoreItem = z.infer<typeof favoriteStoreItemSchema>;

export const favoriteStoreListResultSchema = z.object({
    favoriteStores: z.array(favoriteStoreItemSchema),
    nextCursor: z.string().nullable(),
});
export type FavoriteStoreListResult = z.infer<typeof favoriteStoreListResultSchema>;
```
> `favorite.ts` 가 기존 `like.ts` 를 **대체**한다(D1). `packages/shared/src/index.ts` 의 `export * from './contracts/like';` 는 `favorite` 로 교체.

## Decisions (D 항목)

- **D1 — `like` → `favorite` DRIFT (정본 우선, 기존 자산 교체)**
  - 기존 `packages/shared/src/contracts/like.ts`: `PATCH` body `{ liked }`, 응답 `{ storeId, liked }`, 엔드포인트 `/stores/:id/like`.
  - 정본 API명세: `POST /stores/:id/favorite`, **body 없음**, 응답 `{ storeId, isFavorite }`.
  - **drift 3건**: 메서드(PATCH→POST), 응답 필드(`liked`→`isFavorite`), 엔드포인트(`/like`→`/favorite`).
  - **사용처 전수 조사(2026-06-02)**: 기존 `like` 자산의 실제 소비자는 **`app/(user)/my/favorites/page.tsx` 단 한 곳**(MOCK 하드코딩 임시 placeholder, 이번 기능이 통째로 교체할 화면). 공방 상세 등 다른 화면 사용처 **0건**(grep 확인). 실 BE 연동 없음(MSW only).
  - **✅ 확정 (2026-06-02, 사용자 선택 A)**: **즉시 삭제·교체**. `like.ts` 삭제 → `favorite.ts` 신설, `index.ts` 재노출 교체. `features/store/toggle-like/` → `toggle-favorite/` 교체(`LikeToggleButton`→`FavoriteToggleButton`, `useToggleLike`→`useToggleFavorite`, `toggleLike`→`toggleFavorite`). MSW `POST /like`+`setLike`+`likedStores` → `POST /favorite`+`toggleFavorite`. favorites page 신규 작성(어차피 이번 범위). deprecate 단계 불필요(유일 소비자가 교체 대상이라 죽은 코드 두 벌 유지 이득 0).
- **D2 — 목록 응답 vs 기능명세 표시필드 격차 (BE 필드 추가 vs FE 표시 생략)**
  - 기능명세는 목록 카드에 **평점 / 리뷰 수 / 공방 대표 클래스 정보 / 사용자 찜 상태** 표시를 요구.
  - 정본 `favorite-stores` 응답은 `favoriteId / storeId / name / imageUrl / address / createdAt` 만 — **평점·리뷰수·대표 클래스 없음**. (찜 상태는 목록에 있는 모든 항목이 찜됨이므로 카드의 찜 버튼은 항상 `isFavorite: true` 로 가정.)
  - **Figma 정본 렌더(`8505:19308` + 마이 Description 표) 확인 결과**: 찜 목록 카드는 **썸네일 + 공방명 + 주소 + 찜 버튼**만 렌더. **평점·리뷰수·대표 클래스 UI 없음.** 카테고리 태그도 실제 렌더 화면에는 노출 안 됨(컴포넌트 내부 placeholder 잔재).
  - **✅ 확정 (UI 기준, 2026-06-02)**: 옵션 **(B)** — FE 는 평점/리뷰수/대표클래스 **표시 생략**. 카드 = 썸네일 + 공방명 + 주소 + (카테고리 태그) + 찜 버튼.
  - **D2-b(카테고리) 확정: `category` 추가** — 카드에 카테고리 태그를 렌더하므로 BE 응답에 `Store.category` 추가 요청. 타 도메인(`reservation-list.category`)이 이미 사용 중이라 정합. → contract 는 **7필드**(`favoriteId/storeId/name/category/imageUrl/address/createdAt`). (사용자 확인: "다른 곳도 추가한 듯".)
- **D3 — 낙관적 업데이트(Optimistic Update) 채택 여부**
  - 기능명세: "변경 즉시 반영", "등록 시 목록 즉시 반영, 해제 시 목록에서 제거", **"낙관적 업데이트 적용 여부 정의 필요"**.
  - 기존 `LikeToggleButton` 은 이미 로컬 state 기반 낙관적 토글 + 롤백 구현.
  - **Figma 정본 렌더 + Description #11 확인 결과**: #11 "찜한 공방 목록 해제 Btn → 클릭 시 찜한 공방 해제 / **상태 변경 반영 완료 시 toast 노출**". 토스트 `"'{공방명}' 찜 해제되었어요"`. **취소(undo) 버튼은 렌더 화면에서 숨김**(컴포넌트 프로퍼티만 존재, 디자인 미사용).
  - **✅ 확정 (UI 기준, 2026-06-02)**: 낙관적 업데이트 **채택, 언두 미포함**. ① 토글 버튼 즉시 아이콘 반전. ② **목록에서 해제 시 즉시 제거**(react-query `setQueryData` 로 무한쿼리 페이지에서 항목 제거). ③ **상태 변경 반영 완료(성공) 시 `"'{공방명}' 찜 해제되었어요"` 토스트 노출**(undo 버튼 없음). ④ 실패 시 자동 복원(항목 되돌림) + 에러 토스트. 재찜(등록) 시 토스트 문구는 디자인 미정 → "'{공방명}' 찜 등록되었어요" 가정(D3-b, 사소).
- **D4 — 토글 404/409 스펙 미정**
  - 정본: 삭제·비공개 공방 찜 불가하나 404/409 응답 본문이 비어있음(미정). 목록 조회 400/404/409 도 미정.
  - **결정 필요**: BE 가 비공개/삭제 공방 찜 시 404 인지 409 인지, error code·message 확정. FE 토스트 메시지·롤백 분기 고정에 필요. **BE 답변 대기.**
- **D5 — 빈 상태 화면만 미확보 (카드/목록/토스트는 Figma 정본 확보)**
  - **확보됨**: 목록 화면(`8505:19308`) — 카드 레이아웃(328×80, 썸네일 80×80 r12, 공방명 16/SemiBold, 주소 12/Regular, 찜 버튼 40×40 r999 overlay@30% heart-fill), 카드 gap 16, 콘텐츠 padding 16, 해제 토스트(§Design tokens 참조).
  - **여전히 미확보**: **빈 목록(empty state) 화면** — 본 프레임에 없음. 무한스크롤 로딩 인디케이터 디자인도 미확보.
  - **결정 필요**: 빈 상태 Figma 정본 확보(문구·일러스트·CTA). 미확보 시 카드/목록은 착수 가능하나 빈 상태는 임시 placeholder 후 디자인 확정 시 교체.
- **D6 — 토글 응답 봉투 형태**
  - 정본 200 예시가 `data` 객체 본문(`{ storeId, isFavorite }`)만 제시. 다른 엔드포인트(`ok()` 공통 봉투)와 정합 위해 `data` 에 래핑 가정.
  - **결정(보정 가정)**: 공통 봉투 `data` 에 `{ storeId, isFavorite }`. BE 확인 시 고정.
- **D7 — 목록 페이지네이션 `hasMore` 부재 (reservation-list 와 drift)**
  - reservation-list contract 는 `{ ..., nextCursor, hasMore }`. favorite-stores 정본은 `nextCursor` 만(`hasMore` 없음).
  - **결정(보정 가정)**: `nextCursor === null` 이면 다음 페이지 없음으로 판정(`getNextPageParam` 이 `nextCursor ?? undefined`). `hasMore` 추가 요청 불필요. limit 기본값은 정본 10 vs 팀 공통 `DEFAULT_PAGE_SIZE`(20) drift — reservation-list 선례(공통 상수 우선) 따라 **20 권장**, BE 확인.

## Risks

- **like → favorite 마이그레이션(D1)** 이 기존 자산(`like.ts`, `toggle-like`, `setLike`, MSW `/like`, `LikeToggleButton`) 전반에 걸침. 공방 상세 등 다른 사용처 import 경로 동시 교체 누락 시 빌드/런타임 깨짐. 사용처 전수 확인 필요.
- **D2 표시필드 격차** 미해소 시 카드 UI 확정 불가(평점/리뷰수 노출 여부). 정본 6필드로 갈지 BE 확장할지 선결정 필수.
- **D5 디자인 미확보** → FE 카드/빈 상태/무한스크롤 착수 불가. 디자인 대기.
- **D4 404/409 미정** → 토글 실패 분기(비공개 공방) 메시지 고정 불가. BE 답변 대기.
- 토글이 **body 없는 POST** 이므로 기존 `apiFetch({ body })` 호출부에서 body 생략 처리 확인 필요.
- 낙관적 업데이트 + 무한쿼리 캐시 직접 조작(`setQueryData`) 시 페이지 경계 정합(중복/누락) 주의.
