### 데이터모델 (`apps/api/prisma/schema.prisma` 스냅샷)

**`Review`** (model `reviews`) — 본 plan의 핵심 모델.

| 필드 | 타입 | 비고 |
|---|---|---|
| `id` | `String @id @default(uuid()) @db.Uuid` | path param `reviewId` |
| `reservationId` | `String @unique @map("reservation_id") @db.Uuid` | 예약↔리뷰 **1:1** 관계 (unique). `GET /reservations/{id}/review` 의 lookup key |
| `userId` | `String @map("user_id") @db.Uuid` | 본 plan 가드 — `Review.userId === currentUserId` 비교 |
| `storeId` | `String @map("store_id") @db.Uuid` | 통계 재계산 대상(D9) |
| `rating` | `Int @db.SmallInt` | 1~5. 응답 `review.rating` |
| `content` | `String?` | 최대 500자(`requirements.md` §2). 응답 `review.content` (null 시 빈 문자열로 보정 검토) |
| `isVisible` | `Boolean @default(true) @map("is_visible")` | 신고/미노출 — 본 plan 범위 외(D10). 본 plan은 노출 분기 추가 안 함 |
| `createdAt` | `DateTime @default(now()) @map("created_at") @db.Timestamptz(6)` | 응답 `review.createdAt` |
| `updatedAt` | `DateTime @updatedAt @map("updated_at") @db.Timestamptz(6)` | 응답 미노출 |
| (relations) | `photos ReviewPhoto[]`, `reservation Reservation`, `store Store`, `user User` | photos 응답 포함, store/user 응답 미노출 |

**`ReviewPhoto`** (model `review_photos`) — 리뷰 사진. 삭제 시 cascade.

| 필드 | 타입 | 비고 |
|---|---|---|
| `id` | `String @id @default(uuid()) @db.Uuid` | 응답 `review.photos[].id` |
| `reviewId` | `String @map("review_id") @db.Uuid` | FK → `Review` |
| `imageUrl` | `String @db.VarChar(1000) @map("image_url")` | 원본 URL. 응답 `review.photos[].imageUrl`. 리사이징은 next/image 위임 |

**Soft-delete 영향(D7)**: hard-delete 채택 시 위 schema 변경 없음. soft 채택 시 `Review` 에 `deletedAt: DateTime?`/`status: ReviewStatus` 추가 + GET use-case에서 `where: { deletedAt: null }` 적용 필요.

### 엔드포인트 A — 리뷰 상세 조회

`GET /reservations/{reservationId}/review` — 인증 사용자 본인 예약의 리뷰 1건 상세. (선행 plan D4 결정. 정본 부재로 본 plan에서 SSOT 격상 — D1.)

**Headers:** `Accept: application/json`, `Authorization: Bearer {accessToken}`

**Path Parameters:**
- `reservationId: string(uuid)`

**Query Parameters:** 없음.

**Request Body:** 없음.

**시스템 처리:**
1. 토큰으로 사용자 식별 (AuthGuard) — 미인증 시 `401 UNAUTHORIZED`(D5 보정).
2. `reservationId` 로 예약 조회. 비존재 또는 본인 예약 아님 시 `403 FORBIDDEN` 또는 `404` 분기 (선행 plan 가드 동일 채용).
3. `Review` lookup: `findUnique({ where: { reservationId } })`. 비존재 시 `404 REVIEW_NOT_FOUND`.
4. soft-delete 채택 시 (D7) `deletedAt IS NULL` 필터 추가.
5. `ReviewPhoto` include + `sortOrder ASC` 정렬.
6. 응답 직렬화: 공통 봉투 + `data.review`.

**응답 200 OK — 공통 봉투 (정본 부재 — 선행 plan D4 BE 결정 그대로):**

### 엔드포인트 B — 리뷰 삭제

`DELETE /reviews/{reviewId}` — 인증 사용자 본인 리뷰 1건 삭제. (API명세 2 정본 그대로.)

**Headers:** `Accept: application/json`, `Authorization: Bearer {accessToken}`

**Path Parameters:**
- `reviewId: string(uuid)`

**Query Parameters:** 없음.

**Request Body:** 없음.

**시스템 처리 (API명세 2 정본 그대로):**
1. 토큰으로 사용자 식별 (AuthGuard).
2. `reviewId` 로 리뷰 조회 + 소유자 검증 (`Review.userId === currentUserId`). 미일치 시 `403 FORBIDDEN`. 비존재 시 `404 REVIEW_NOT_FOUND`.
3. `reviews` + 연결된 `review_photos` row 삭제 (hard-delete — D7).
4. S3 에서 리뷰 사진 원본·썸네일 삭제 (D8 — BE 동기/비동기 결정).
5. 공방·프로그램 평균 별점·리뷰 수 재계산 (D9 — BE 동기/비동기 결정).
6. 삭제 완료 응답 반환.

**응답 200 OK — 공통 봉투 (정본 그대로):**
```json
{
  "statusCode": 200,
  "timestamp": "2026-06-02T10:00:00.000Z",
  "path": "/reviews/review-uuid-001",
  "message": "리뷰가 성공적으로 삭제되었습니다.",
  "data": null,
  "error": null
}
```

**에러 (정본 + D5/D6 보정):**

| status | code | message | 비고 |
|---|---|---|---|
| 401 | `UNAUTHORIZED` | "인증이 필요합니다." | 정본 미명시 — D5 보정 |
| 403 | `FORBIDDEN` | "해당 리뷰에 대한 접근 권한이 없습니다." | 정본 그대로 |
| 404 | `REVIEW_NOT_FOUND` | "리뷰를 찾을 수 없습니다." | 정본 그대로. **이미 삭제된 리뷰**(기능명세 2 예외)도 hard-delete 채택 시 자연스럽게 이 분기 — D6/D7. |
| 500 | `INTERNAL_SERVER_ERROR` | "리뷰 삭제 중 서버 오류가 발생했습니다." | 정본 그대로 |
