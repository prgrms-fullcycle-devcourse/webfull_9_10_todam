**시스템 처리 (정본):**

1. 인증 토큰으로 사용자 식별
2. `artworkId`로 `Artwork` 조회 → 연결된 `Reservation.userId == requester.userId` 검증 (불일치 시 403)
3. `ArtworkLog`를 시각 순 조회, 각 로그에 연결된 `ArtworkPhoto` 묶음 (D3 필터 적용)
4. 내부 상태(`ArtworkStatus`)를 `displayState` 노출 문구로 치환
5. 완료/현재/미완료 단계 구분 (D4 — 정렬·미완료 표현 방식 결정)
6. 내부 메모(`internalMemo`/`memo`)·변경자(`changedBy`) 등 운영 정보 비포함

**에러 응답:**

| status | error code | message |
|---|---|---|
| 401 | `UNAUTHORIZED` | "인증이 필요합니다." — **D2: 정본 미명시, AuthGuard 표준 보정** |
| 403 | `FORBIDDEN` | "해당 작품에 대한 접근 권한이 없습니다." |

**제한:**
- 제작단계별 이미지는 최대 5개까지 등록 가능 (요구사항 §6) — 본 plan은 조회만이므로 입력 검증 없음, 응답 photos 길이만 0~5 보장 (BE 신뢰).
- 등록된 제작 단계가 없는 경우 → `timeline: []` 빈 배열 (FE는 EmptyState 처리).

## Risks

- **D1 미해소 시 확대보기 UX 미완성** — `imageUrl` 응답에 없으면 사용자가 썸네일을 320×320 모달에 띄우게 됨(64×64를 5배 → 저화질 확정). 폴백 임시 구현 가능하나 production 릴리즈 전 BE 정본 갱신 필수.
- **D5 RESERVED 라벨 미정 시 렌더 깨짐 가능** — VISITED/COMPLETED는 디자인 확정. RESERVED는 timeline 등장 여부 + 라벨 미정 → BE 매퍼 작성 시 임시 처리 금지(선행 plan `나의 예약조회.md` 정책 그대로 적용).
- **timeline 정렬·미완료 표현(D4) 정책 미정** — BE 구현 시 임의 결정하면 FE와 어긋남. 결정 후 contract 보강.
- **`Reservation.status = CANCELED` 케이스의 작품 접근 정책 미명시** — 요구사항 §1 displayState 계산은 CANCELED 시 작품 노출 미명시. 본 plan은 정본 contract 그대로(403 미적용 → 200으로 timeline 반환) 가정, BE 결정 시 갱신.
- **응답 본문 사이즈** — `photos[]` 단계당 최대 5개 × 8 ArtworkStatus = 최대 40개. `imageUrl` 추가 시 사이즈 ~2배 증가하나 BE 응답 직접 호출 시 영향 미미(URL 문자열). CDN sizing 캐시 정책은 BE 결정.
- **`current` connector 색 검증 필요** — §Design tokens 표는 Figma JSON 1차 해석. completed→current 사이 connector가 primary-lighter인지 border-default인지 노드 재확인 필요(FE 구현 시).
