## API Contract (스냅샷)

출처: Notion API명세 DB `5852ee66b06c838bb8ec01c6bf4f2e25`, 2026-06-05 스냅샷.

### 공통 응답 봉투

```json
{ "statusCode": 200, "timestamp": "...", "path": "...", "message": "...", "data": null, "error": null }
```

### 엔드포인트 1) `POST /auth/password/reset-request` — 비밀번호 재설정 메일 발송

- 인증: 불필요(Guest). AuthGuard 미적용.
- req body:
  ```json
  { "email": "user@example.com" }
  ```
- 시스템 처리:
  1. `email` 필수값 + 이메일 형식 검증
  2. 가입된 활성 유저 확인
  3. 가입 유저 실존 시: 1회용 보안 토큰 + 만료 15분 → **Redis** (`password:reset:token:{token}` → `{userId, email}`, TTL 900s) 저장, 재설정 링크(`https://todam.app/reset-password?token={resetToken}`) 메일 발송 (현 scope에서는 console/log stub — SES 실연동 backlog)
  4. 미가입 이메일이어도 동일 200 응답 반환(Enumeration 공격 방지)
- 200 res:
  ```json
  {
    "statusCode": 200,
    "message": "입력하신 이메일 주소로 회원 정보가 있는 경우, 비밀번호 재설정 메일이 성공적으로 발송됩니다.",
    "data": null,
    "error": null
  }
  ```
- 에러:
  - `400 INVALID_EMAIL_FORMAT` — "올바르지 않은 이메일 형식입니다."
  - `500 INTERNAL_SERVER_ERROR` — "메일 발송 외부 모듈 연동 오류 혹은 서버 시스템 에러"

---

### 엔드포인트 2) `POST /auth/password/reset` — 새 비밀번호 설정

- 인증: 불필요(Guest). AuthGuard 미적용.
- req body:
  ```json
  {
    "token": "secret-security-token-sent-via-email-001",
    "newPassword": "NewSecurePassword123!"
  }
  ```
- 시스템 처리:
  1. `token`, `newPassword` 필수값 + 형식 검증
  2. Redis/저장소에서 토큰 조회 → 존재 여부 + 만료(15분) 검증
  3. 토큰에 바인딩된 `userId` 역추출 → 유저 레코드 확보
  4. `newPassword` 복잡도 검증(영문+숫자+특수문자, 8자 이상)
  5. 기존 비밀번호와 동일 여부 `bcrypt.compare` 검증 → 동일이면 400 `PASSWORD_ALREADY_USED`
  6. 신규 비밀번호 bcrypt 해싱 후 `users.password` 갱신
  7. 해당 유저의 모든 Refresh Token 일괄 삭제(전 기기 강제 로그아웃)
  8. 사용된 토큰 즉시 삭제(1회성 보장)
  9. 성공 응답 반환
- 200 res:
  ```json
  {
    "statusCode": 200,
    "message": "비밀번호가 성공적으로 재설정되었습니다. 새로운 비밀번호로 다시 로그인해주세요.",
    "data": null,
    "error": null
  }
  ```
- 에러:
  - `400 INVALID_PASSWORD_FORMAT` — "비밀번호 규격 조건(영문, 숫자, 특수문자를 혼용하여 8자리 이상)을 만족하지 못했습니다."
  - `400 PASSWORD_ALREADY_USED` — "기존에 사용하던 비밀번호와 동일한 비밀번호로는 변경할 수 없습니다."
  - `401 INVALID_OR_EXPIRED_TOKEN` — "유효하지 않거나 이미 시간 만료된 보안 토큰 정보입니다. 재설정 요청을 다시 시작해 주세요."
  - `500 INTERNAL_SERVER_ERROR`

### BE 구현 현황 vs API Contract — Drift 분석

현재 구현: `apps/api/src/modules/auth/application/use-cases/reset-password-request.use-case.ts`, `reset-password.use-case.ts`, `presentation/dto/reset-password-request.dto.ts`, `reset-password.dto.ts`

| # | 항목 | API명세(정본) | 현재 구현 | 심각도 |
|---|------|--------------|-----------|--------|
| D1 | reset-request 토큰 방식 | 1회용 URL 토큰(`resetToken`) → 링크 발송 | 6자리 숫자 코드 Redis 저장 후 코드 발송(`sendPasswordResetCode`) | 🔴 |
| D2 | reset-request 링크 URL | `https://todam.app/reset-password?token={resetToken}` | 단순 코드 발송(링크 없음) | 🔴 |
| D3 | reset 요청 바디 | `{ token, newPassword }` | `{ email, code, newPassword }` | 🔴 FE 연동 시 즉시 깨짐 |
| D4 | 토큰 만료 | 15분 | 5분(`RESET_CODE_TTL_SECONDS = 300`) | 중 |
| D5 | 기존 비밀번호 재사용 차단 | `bcrypt.compare` 후 `PASSWORD_ALREADY_USED` (400) | 미구현 | 중 |
| D6 | 비밀번호 복잡도 검증 | 영문+숫자+특수문자+8자 이상 | `MinLength(8)`/`MaxLength(100)` 만(복잡도 regex 없음) | 중 |
| D7 | reset 에러 코드 | `401 INVALID_OR_EXPIRED_TOKEN` | `BadRequestException(400)` "유효하지 않거나 만료된 인증코드" | 중 |
| D8 | 메일 발송 | AWS SES 실발송 | `console.log` stub | 중 |
| D9 | 세션 무효화 | 전 기기 Refresh Token 일괄 삭제 | `updatePasswordAndRevokeTokens` 구현됨 — 일치 | 해소 |

**최우선(🔴):** D1~D3는 연동 블로커. 현재 구현은 "코드" 기반이나 명세는 "URL 토큰" 기반. req body 구조 자체가 다름 → BE use-case + DTO + Redis 키 방식을 재설계해야 FE 연동 가능.
