# Feature Plan: 파트너 센터 이동하기 / 공방 등록하기

## Summary

- Goal:
  - **파트너 센터 이동하기**: 마이페이지 허브에서 `isPartner=true`인 User가 "파트너 센터 이동하기" 링크를 탭하면 `/partner`로 이동한다. 이미 `MyPageHub.tsx`에 UI가 구현되어 있으며(`isPartner` 조건부 노출 + `router.push('/partner')`) 실 API(`GET /users/me`의 `isPartner` 필드) 연동이 남아 있다.
  - **공방 등록하기 (첫 등록 / 추가 등록)**: User(파트너 미신청) 또는 APPROVED 파트너가 공방 등록 4단계 플로우(사업자 정보 → 공방 정보 → 영업 정보 → 예약 정보)를 완료하고 검수 제출(`PENDING`)까지 진행한다. FE(`StoreRegistrationFlow`) 및 BE(`POST /stores`, `POST /partner/stores/{storeId}/submit` 등)가 이미 구현·연동되어 있음. **기존 구현 보완·갭 해소**가 주목적.
  - 두 기능은 **마이페이지 D8(파트너센터 노출조건·목적지) 해소**와 **공방 등록 기존 구현 완성도 점검**을 함께 처리한다.

### 데이터모델

| 모델 | 핵심 필드 | 비고 |
|---|---|---|
| `Store` (`stores`) | `id`(uuid), `partnerId`, `name`(2~40자), `slug`(4~40자, unique), `address`, `latitude`, `longitude`, `phone`, `description`(선택), `convenienceInfo`(JSON: parking/pet/wifi), `autoConfirm`(bool), `cancelDeadlineDays`(int), `reservationIntervalMinutes`(60/90/120/180), `maxCapacityPerSlot`(int), `status`(DRAFT/PENDING/PUBLISHED/SUSPENDED), `createdAt`, `updatedAt` | 공방 상태 전이: DRAFT→PENDING(submit), PENDING→PUBLISHED/REJECTED(admin) |
| `OperatingHour` (`operating_hours`) | `storeId`, `dayOfWeek`(MON~SUN), `openTime`(HH:mm), `closeTime`(HH:mm), `breakStart`(optional), `breakEnd`(optional) | 공방과 1:N |
| `BusinessDocument` (`business_docs`) | `storeId`, `partnerId`, `businessNumber`(10자리숫자), `businessName`, `ownerName`, `businessAddress`, `email`(optional), `documentUrl`(S3 URL, optional) | OCR 추출·진위확인 결과 저장 |
| `StoreImage` (`store_images`) | `storeId`, `isThumbnail`(bool), `imageUrl`, `status`(PENDING/UPLOADED) | presigned 업로드 후 confirm으로 UPLOADED 전이 |
| `Partner` (`partners`) | `userId`, `status`(PENDING/APPROVED/REJECTED/SUSPENDED/TERMINATED) | 첫 Store 생성 시 자동 생성(PENDING) |

### 엔드포인트

#### 1) `POST /stores` — 공방 초안 생성 (Notion 미등록, BE 구현 기준)

User(또는 PENDING 파트너)가 공방 초안을 생성한다. Partner 엔티티가 없으면 자동 생성(status=PENDING).

**Guards:** `@UseGuards(AuthGuard)`
**Headers:** `Content-Type: application/json`, `Authorization: Bearer {accessToken}`

**Request body:**
```json
{
  "name": "흙담 공방",
  "slug": "흙담-studio",
  "description": "도자기 체험 공방입니다.",
  "phone": "02-1234-5678",
  "address": "서울특별시 성동구 성수이로 12길 34",
  "latitude": 37.5446,
  "longitude": 127.0556,
  "convenienceInfo": { "parking": true, "pet": false, "wifi": true },
  "autoConfirm": false,
  "cancelDeadlineDays": 1,
  "reservationIntervalMinutes": 60,
  "maxCapacityPerSlot": 6,
  "operatingHours": [
    { "dayOfWeek": "MON", "openTime": "10:00", "closeTime": "19:00", "breakStart": "13:00", "breakEnd": "14:00" }
  ],
  "businessDocument": {
    "businessNumber": "1234567890",
    "businessName": "흙담",
    "ownerName": "김토담",
    "businessAddress": "서울특별시 성동구 성수이로 12길 34",
    "email": "hello@todam.app",
    "documentUrl": "https://cdn.todam.app/docs/xxx.jpg"
  }
}
```

> `slug` 미입력 시 nanoid(12자 hex) 자동 생성. `documentUrl` 미입력 시 null. `description` 선택.

**201 Created (data 본문):**
```json
{
  "store": {
    "id": "a1b2c3d4-...",
    "partnerId": "p1...",
    "name": "흙담 공방",
    "slug": "흙담-studio",
    "status": "DRAFT",
    "createdAt": "2026-06-05T10:00:00.000Z"
  }
}
```

**에러:**

| status | code | message |
|---|---|---|
| 400 | `BAD_REQUEST` | "사업자등록증 파일이 업로드되지 않았습니다." (documentUrl S3 미존재 시) |
| 400 | `PARTNER_NOT_APPROVED` | APPROVED가 아닌 파트너가 추가 공방 등록 시도 시 |
| 401 | `UNAUTHORIZED` | "인증 정보가 유효하지 않거나 만료되었습니다." |
| 409 | `SLUG_CONFLICT` | "slug가 이미 사용 중입니다." |
| 500 | `INTERNAL_SERVER_ERROR` | |

#### 6) `GET /partner/onboarding` — 온보딩 상태 조회 (Notion 미등록, BE 구현 기준)

파트너 검수 게이트용. 무파트너/PENDING/REJECTED 모두 접근 가능. AppShell 진입 시 호출.

**Guards:** `@UseGuards(AuthGuard)`

**200 OK (data 없음 — 응답 직접 반환):**
```json
{
  "statusCode": 200,
  "data": {
    "partnerStatus": "PENDING",
    "store": {
      "id": "a1b2c3d4-...",
      "status": "PENDING",
      "rejectedReason": null
    }
  }
}
```

> `partnerStatus`: `null`(무파트너) | `PENDING` | `APPROVED` | `REJECTED` | `SUSPENDED` | `TERMINATED`.
> `store`: 최신 생성 공방 1건. 없으면 `null`.
> `rejectedReason`: `store.status === REJECTED`일 때만 값, 그 외 `null`.

**에러:** 401 `UNAUTHORIZED` only.

## Risks

- **OCR 미구현 갭**: 기능명세·API명세는 OCR/사업자진위확인을 필수로 명시하나, 현재 FE·BE는 presigned 직접 업로드로 우회. 사업자 진위확인 없이 공방 등록이 가능한 상태 → 운영 리스크. D2 결정 필수.
- **Notion 미등록 API**: `POST /stores`·`GET /partner/onboarding`이 명세 DB에 없어 다른 팀원이 contract를 확인할 SSOT 부재. D4로 등록 요청 선행.
- **파트너 센터 이동 노출 조건 edge case**: `isPartner=true`지만 `Partner.status=SUSPENDED/TERMINATED`인 경우 파트너 센터 접근 가능 여부. `AppShell`은 `partnerStatus`로 무파트너/PENDING/REJECTED만 차단 — SUSPENDED/TERMINATED 케이스 미처리 가능성(D1).
- **추가 공방 등록 route guard**: `/partner/stores/new`에 별도 APPROVED guard 없음. AppShell의 PartnerGuard가 없으면 SUSPENDED 파트너도 UI 진입 가능. 확인 필요(D5).

## Open decisions (사람 결정 대기 — 추측 금지)

- **D1. SUSPENDED/TERMINATED 파트너의 파트너센터 접근 허용 여부**: `AppShell`은 `partnerStatus=null/PENDING/REJECTED`만 차단. `SUSPENDED/TERMINATED` 케이스는 현재 `/partner` 진입 허용 상태. 마이페이지 "파트너 센터 이동하기" 링크도 `isPartner`(APPROVED 여부)만 체크하므로 SUSPENDED이면 노출 안 되나, URL 직접 접근 시 gate 없음. 정책 결정 필요.
- **D2. OCR/사업자진위확인 구현 여부**: API명세는 `POST /partner/stores/{storeId}/documents`(OCR 통합)를 명시하나, 현재 FE·BE는 presigned 직접 업로드로 우회. (a) OCR 통합 BE 구현 후 FE 연동, (b) presigned 방식을 정본으로 확정(API명세 revise). 결정 전까지 OCR 관련 기능 Out.
- **D3. `POST /partner/stores/{storeId}/documents` guard**: Notion 명세는 `AuthGuard + PartnerGuard` 암시. 첫 등록(PENDING 파트너)도 사용 가능해야 한다면 `AuthGuard` only로 완화 필요. 현재 presigned 우회(`POST /partner/business-documents/images`)는 AuthGuard only.
- **D4. Notion 미등록 API 등록**: `POST /stores`·`GET /partner/onboarding` 2건 Notion API명세 DB 등록 필요. 등록 후 이 plan contract 스냅샷 갱신 필요. 담당자 확인.
- **D5. 추가 공방 등록(`/partner/stores/new`) route guard**: `PartnerGuard(APPROVED)` 없이 접근 가능 여부. BE `POST /stores` use-case 내부에서 `PARTNER_NOT_APPROVED` 에러를 반환하므로 BE 레벨에서는 차단되나, FE 라우트 레벨 guard 미적용 여부 확인.
- **D6. 파트너 센터 이동하기 비 APPROVED 진입점 존재 여부**: ✅ **해소(사용자 결정 2026-06-05)** — 마이페이지 허브 메뉴를 권한별로 분기 노출한다.
  - 파트너 권한 있음(`isPartner=true`) → **"파트너 센터로 이동하기"** 노출 → `/partner`.
  - 파트너 권한 없음(`isPartner=false`) → **"공방 등록하기"** 노출 → `/apply`.
  - `/partner` 진입 후 capability/status 분기(목적지 화면 — 별도 "대시보드 조회" plan 소관, 본 plan은 라우팅까지):
    - `capability == false`(파트너 미생성) → 공방 등록 뷰.
    - `capability == true`:
      - `PENDING` → 신청 완료 뷰.
      - `APPROVED`:
        - 클래스 없음 → 대시보드 뷰 + 클래스 등록 팝업.
        - 클래스 있음 → 대시보드 뷰.
  - → `MyPageHub.tsx`는 현재 `isPartner=true`일 때만 링크 노출. **갭: `isPartner=false`일 때 "공방 등록하기"(→`/apply`) 메뉴 추가 필요.**
